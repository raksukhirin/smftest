01

วงจรธุรกิจ — ข้อมูลไหลอย่างไร

4 หน้าจอเป็นสายทำงานหลัก (transactional) เรียงตามลำดับ · อีก 2 หน้าอ่านจากทุกหน้าแบบ read-only. ลูกศรบอกว่า “อะไรไหลต่อ” — และเส้นสีแดงคือ D2: ใบเสนอราคายัง Active แต่ Rate ต้นทางตายไปแล้ว

ข้อมูลไหลต่อ (transactional) แชร์สถานะ (localStorage) อ่าน (read-only) D2 · Rate ตายทั้งที่ Quote ยังใช้ได้ D12 · actual วนกลับมาเทียบ estimated

04

Data layer & สถานะที่แชร์กัน

ทุกหน้าอ่านจากไฟล์ JSON ชุดเดียว — เปลี่ยนเป็น SQL Server ภายหลังได้เพราะ field ตั้งชื่อ camelCase ตรงกับ DDL

Data — source of truth เดียว

mockup/FPI/data/*.json (rates · quotes · bookings · lane_history · ...)
เสิร์ฟผ่าน http → อ่าน ../data · เปิดจากไฟล์ตรง ๆ → fallback data.js (สำเนาฝัง auto-generated)

⚠ สถานะแชร์ = ต้อง origin เดียวกัน

หน้า 3 ↔ 4 แชร์ localStorage['fpi_booking_gate_v1'] (approve ที่ Inbox → Booking Gate ขึ้นขั้น Credit). คนละ port = คนละ origin = คนละ localStorage — ต้องเสิร์ฟทั้งสองหน้าจาก เซิร์ฟเวอร์ตัวเดียว
